## External routing and persistent indexing

The guard registers `beforeInitialize` only and the candidate uses a static pool fee. Uniswap Labs currently documents automatic consideration for eligible hooked pools unless the hook address starts with `0x91` or the hook uses the listed swap, return-delta or dynamic-fee capabilities. This makes the initialization flags compatible with the published screening rules subject to the final address prefix and live pool eligibility. Assess the exact candidate's deployed hook address independently and keep hosted support **unknown** until a third-party service returns evidence for the authorized pool. The chain/version listing and direct fork swaps establish the two prerequisites they each measure. [Uniswap routing for hooked pools](https://support.uniswap.org/hc/en-us/articles/48291859140621-Routing-for-hooked-pools) · [Uniswap API quote fields](https://developers.uniswap.org/docs/api-reference/aggregator_quote)

After separate deployment authorization, verify hosted routing via a read-only quote specifying chain `4663`, Router `2.1.2`, `V4` and hooked pool support. Verify that the route includes the intended PoolManager and matches the canonical PoolId derived from `currency0`, `currency1`, `fee`, `tickSpacing` and `hooks`. Verify exact-path calldata, sender and recipient, amount bounds and deadlines before any future execution approval. Hosted index evidence needs the same full key, funded liquidity evidence and canonical event identities from a named service. A token address or symbol alone cannot identify a v4 pool. The in-house new-engine index currently has isolated PostgreSQL evidence for receipts, restart, stale RPC, missing traces and rollback. Future activation requires approved runtime provenance, separately scoped checkpoints, one writer, authenticated reads and restore drills. ## Reproduce the public probe

Run from the review branch with Node `22.23.2` and the existing `@rmt/launch-website` dependencies (`viem` `2.55.5` in the pinned lockfile). Omit the positional block to inspect the current head. The fixed historical argument below can fail once official RPC state is pruned. The report records the block actually read and the failure from each provider. The script exits unsuccessfully when official and at least one alternate cannot jointly confirm that block and all six runtime identities. Method-specific archive, trace and receipt gaps are reported separately. The script uses fixed HTTPS sources and read methods, bounds each response to 192 KiB and makes no credentialed requests.

```sh
pnpm install --frozen-lockfile
node docs/evidence/rmt-task039/probe-robinhood-4663.mjs 114441768
```
