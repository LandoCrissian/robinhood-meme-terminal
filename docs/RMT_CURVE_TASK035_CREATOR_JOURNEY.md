## Creator review

`/create-token` collects a name, ticker, fixed supply, optional project URI and treasury allocation. Description and artwork URL are kept in this browser's draft. Artwork uses the existing token monogram and sends no request to the entered URL. The page sends only the six candidate fields to its same-origin validation route. Responses are bounded and uncached. The handler performs no storage, metadata fetch, wallet access, RPC call or transaction construction. Users can edit or clear the draft, recover it from browser storage, and retry validation without losing fields.

The approved analysis source is [#592](https://github.com/LandoCrissian/robinhood-meme-terminal/pull/592) at `5fe80e04713cd0d72dedc087ede3a54ba2d6920d`. [#593](https://github.com/LandoCrissian/robinhood-meme-terminal/pull/593) and [#594](https://github.com/LandoCrissian/robinhood-meme-terminal/pull/594) preserve the exact checked-in Solidity tree `e98de2eaedcf9d233bac0860094e7179db2ab562`. Those branches are reference and test inputs. This branch does not bring their contract or wallet code into the website.

All amounts, beneficiary addresses and signer assignments require production approval. Already deployed RMT assets retain their original rules.

## New-engine reads

`apps/indexer/src/curve-launch-evidence.ts` is an opt-in registration verifier, separate from the historical V6 worker code. It expects an explicit 4663 factory, deployment block and hash, registry, runtime hashes and protocol version. It binds the successful transaction and matching creation, registry and fee logs to a canonical block, requires a qualified checkpoint and verifies the RPC chain. The tests supply typed local fixtures and test inconsistent chain and receipt evidence. The fee event and transaction value are registration evidence. A native refund still requires independent transfer-trace evidence for wallet settlement. Ethereum L1 finality remains unverified.

The new-engine display distinguishes draft, confirmed creation, active curve, ready for graduation, graduated with a verified Uniswap v4 position observation, and unknown. No verified new-engine listings are published. There is no production factory binding, writer registration, polling, schema migration or public new-engine API in this branch. A later read activation must add separately scoped durable replay and rollback to the existing Railway writer, audit source and receipt coverage, and prove canonical engine and immutable PoolKey and position evidence before making lifecycle observations public. Keep the present V6 data and checkpoints separate.
