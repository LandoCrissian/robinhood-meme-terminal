# Settlement rollback regressions after #652

- `testFundedAcceptanceCannotChangePredecessorTokenDebit` and `testFundedAcceptanceCannotChangeSuccessorTokenCredit` inject one atomic token through a separately authorized holder after the successor accepts the native backing. Both paths must revert at exact settlement, leave routes, balances, ledger and migration authorization intact, and allow retry under the same signed proposal. These exercise the two pre-acceptance snapshots reported as `be7b3e4ab448` and `7f0d82532758`. [Migration tests](../../../packages/contracts/test/RMTLaunchMigrationReadiness.t.sol)
- `testPoolBalancePerturbedDuringInventoryPullRollsBack` changes the shared manager's balance during the inventory pull, before PositionManager settlement. It requires full rollback of balances, pool initialization, position, fee ledger and allowances, then checks a successful retry. It extends finding `1e179df9a2b6` with an ingress-phase fault. [Funding tests](../../../packages/contracts/test/RMTV4CurveGraduationV1.t.sol)

These regressions inject code in isolated tests to reach specific failure branches. Production Solidity, dependency pins and review inputs retain their exact hashes. A fresh 0.11.5 run of the 4663 compiler closure reproduced all 233 finding IDs. The `reentrancy-balance`, `incorrect-exp` and `incorrect-shift` detector source files also match the corresponding files in 0.11.6. The four pinned arithmetic findings and the active-engine findings still block the unchanged strict gate. [Slither 0.11.6 release](https://github.com/crytic/slither/releases/tag/0.11.6)
