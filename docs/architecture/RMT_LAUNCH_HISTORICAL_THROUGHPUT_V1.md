## Scheduler and safety

The existing process has one additional timer, not another indexer/service. Each history window admits work for at most five seconds, at most eight sequential ranges, with at least one second between range starts and a one-second quiet interval between windows. A final admitted range may finish after the admission deadline; it is still bounded and preemptible. No overlapping history windows or parallel range bursts.

Source groups rotate by deterministic source ID and coalesce only equal cursors. Every source receives a turn, including divergent recovery cursors. Selection state is only a fairness optimization; canonical evidence and cursors remain durable PostgreSQL authority. Restart reloads committed cursors. Live work wakes any history wait and takes the next slot. A live request can interrupt block reads/event insertion before commit, discarding only that uncommitted range. Its cursor remains unchanged.

History uses the same configured RPC, timeout five seconds, zero transport retries, HTTP batches of at most three block reads. The old three-block concurrency bound is retained; history ranges themselves have concurrency one. At most 48 block reads per range: denser ranges are retried at half the size without cursor advancement, and increase gradually on sparse success. This adds headroom above the measured maximum 35 reads while bounding RPC work. No verified history is skipped. The original confirmation, hash checks, atomic event/checkpoint/cursor transaction, deduplication, reorg/ancestor selection and replay functions remain unchanged.

Failures stop the history window and apply 30-second exponential backoff, capped at five minutes. Existing canonical records remain valid. Live reads continue independently. Failure before a window's head read also backs off; unavailable cold source proofs are renewed only by the ordinary/live cycle. Background work requires a healthy ordinary worker and checks the existing logical database limit before each window. The current production connection pool is five; no new configuration is required. Postgres-EHZZ remains the same 5 GB volume and Railway's $20 hard limit is unchanged.

Completed historical coverage disables background RPC admission. The ordinary/live cycle still polls live launches and reloads durable cursors; it re-enables background work when a recovered source or reorg leaves history pending. Regression covers completion, continued live detection and renewed pending history.
