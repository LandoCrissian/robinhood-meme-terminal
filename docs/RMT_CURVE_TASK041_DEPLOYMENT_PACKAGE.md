## Immutable choices and continuity

| Setting | When fixed | What can change |
| --- | --- | --- |
| RMT operating treasury, future reserve, creation fee, official v4 bindings | Deployment of each factory/bootstrap | The existing factory and associated credits retain the same addresses and terms. A later factory may use new constructor inputs, subject to directory admission. An external beneficiary wallet can change its own spending policy if supported. |
| Project creator, treasury address, treasury percentage and supply preset | Token creation | Neither platform governance nor curve migration can replace a beneficiary, change the split or remint supply. A project can rotate owners or adjust threshold within a compatible external smart-account treasury at the same address. A direct EOA address has no equivalent rotation in this architecture. |
| 90/5/5 fee shares, curve terms, pool fee and graduation policy | Compiled into the deployed engine and committed per launch | Asset-bearing migration must preserve economic rules, the original token, balances, backing, unsold inventory, existing credits and both project and platform payees. |
| Three directory signer EOAs, 2-of-3 threshold, registry-to-directory binding | Directory and registry deployment | Signer identities, threshold and registry binding have no setter, proxy, administrator or rotation route. A project's external wallet permissions are separate from directory governance. |
| Factory and successor admission | Directory governance after deployment | Two distinct configured signers can schedule a versioned factory or reviewed successor template, with a two-day delay and bounded execution window. The V1→V2 template is pinned in the factory. V3 and later templates are append-only, sequential and bounded at version 32. Migration requires creator proposal, two configured signer authorizations and another two-day delay. |
| Original LP NFT, canonical PoolKey and principal custody | Graduation, under the deployed engine's policy | The graduation engine retains the position. Fee harvest and claims transfer earnings. The architecture exposes no post-graduation position transfer, principal removal, or migration to another registry. |

One lost signer leaves two required participants and eliminates redundancy. Losing two permanently removes the original directory's quorum. New factory or template admission, migration scheduling, suspension, quorum cancellation and resumption then become unavailable. Previously scheduled actions may still execute inside their permitted window if the relevant state allows. Anyone can clear expired proposals, and creators can cancel their own migration proposals. Unsuspended factories already admitted to the directory can still register launches. Existing curves, pools and beneficiary claims retain their existing execution paths. If discovery is already suspended and quorum is lost, the same directory cannot resume it. A separately deployed directory could govern a new registry. Existing registries, launch commitments and custody have no path to that new registry.

**Freeze decision.** The owner must accept immutable signer continuity, with three independent EOA operators, durable key backups and a practiced recovery plan. If replacing unavailable signers within the same directory is a release requirement, use a separately reviewed design and re-rehearse before deploying this profile. A Safe treasury can change its own owner keys according to its quorum policy. That capability does not transfer an immutable project payout address or rotate a directory EOA.
