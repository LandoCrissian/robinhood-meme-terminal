## Chosen architecture

Reuse the existing RPC authority, factory resolver, cached producer readers, visibility refresh hook, pagination and keyed rows. Exact search may attach separately labelled live contract resolution when inventory has no pool; it never fabricates creation coordinates, writes canonical inventory, alters execution policy or promotes Active. Positive identity quarantine still applies.

The optional live resolution has a 3-second response budget, a 60-second shared cache, at most 128 cache keys, eight concurrent resolutions and eight verified pools per token. Pool validation uses sequential batches of two with the existing batched client, rather than a serial tail or eight parallel validations. Factory lookups use only existing supported V2/V3 factories and the existing WETH/USDG quote authorities. A provider delay retains the verified token identity and the workspace's existing progressive resolution path. No user-driven candidate persistence queue is introduced.

Visible Markets directory: 60s. Visible market enrichment: 60s, matching the shared external cache rather than hammering providers. Visible Launches directory: 30s, matching producer cache granularity and live-lane needs. One in-flight task per lane, bounded request timeout, bounded loaded-window revalidation, failure backoff up to 5 minutes. Hidden/offline tabs make no new reads. Visibility/focus/reconnect trigger immediate revalidation with a minimum 10s gap. No WebSockets/SSE/new service. A root Markets scanner changes from 0.4 to 2 base requests/minute before existing identity enrichment; a Launches scanner adds 2 page reads/minute. More loaded pages increase bounded window reads. Shared server/CDN caches remain intact. These are request estimates, not billing forecasts.

Launch revalidation follows fresh cursors sequentially and atomically publishes the loaded window, capped at eight pages (400 entries), rather than fetching all history. Source availability is revalidated through the existing positive indexed-evidence reader and remains independent of the first page. Lifecycle selection remains available when its last member transitions. A fixed 44px update-control slot prevents pending updates from pushing the scanner.

Reconcile by exact address/launch ID. Existing values update in place. While touching, typing or displaced from scanner top, preserve established order and defer new membership/ranking to a compact fixed-height update control. Exclusions remain authoritative. At top and idle publish current ranking automatically. Search text/focus/caret, pagination window, scope, activity tab, selected asset and trade composer remain owned by existing components.

A genuine Pons refresh exposed another boundary: a launch falling outside the newest 50-entry page was being treated as a deletion during typing. Launches now retains the displayed last-known rows during interaction because a bounded page omission is not canonical invalidation. Idle or explicit publication replaces the window with the current directory. Context changes never retain another source/query's rows. The canonical Market reader does not opt into this behavior: authoritative exclusions still remove rows. Retention remains bounded by the displayed window.

Scanner artwork keeps a visible fallback during its initial load and retains the last loaded image until a replacement decodes successfully. A failed replacement retains the last good artwork. This opt-in behavior covers Market scanner rows and existing Launch rows; the existing authority and non-scanner detail presentation remain unchanged. Controlled acceptance includes a delayed replacement and a failed replacement.

Explore is a native modal dialog styled as a mobile bottom sheet and desktop anchored popover; focus restoration, Escape, outside close and visible primary navigation remain intact. Activity and supported market universe are separate filters; Held uses existing wallet authority, RWA existing registry classification, Projects uses admitted token relationships rather than inventing tokens. Launches retains its first-class destination. No NFT/Project/producer/execution changes.

Scope counts describe positively classified loaded markets, not global producer totals. Unresolved Held reads retain the existing unknown/loading semantics. `Any activity` is an explicit independent activity choice; legacy `view=rwa` links restore RWA + Any activity. New links preserve both `view` and `universe` through browser history.

When no inventory has loaded and the reader is loading or unavailable, scope counts remain unknown rather than displaying false zeroes. The existing outage/recovery acceptance retains its assertions against this boundary.

Controlled browser tests supplement read-only genuine public snapshots. Corrected production is not claimed live before separate deployment authorization.
